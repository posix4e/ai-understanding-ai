# Experiment 2: prospective head-combination prediction protocol

## Scientific scope and models

Test whether an explanation fitted using single-head and all-head corruptions forecasts **unseen** two-head corruptions, sole-head clean rescues/three-head corruptions, and cross-layer corruptions. All model computation runs locally on the MacBook Air CPU. No cloud compute or paid inference API is used. Keep E1 original and amended protocols, failed first attempt, successful later attempt, and results intact.

The model set is fixed to seeds **0,1,2,3,4,5**. Seeds 0–2 are the existing E1 models; seeds 3–5 are additional training replications, using the already selected 2,000-step training schedule and embedding SD 1.0. Each is the same two-layer, four-head, width-64 dictionary transformer. The additional `z` hook caches weighted value aggregation before attention output projection; it must leave weights/state-dict keys and unpatched behavior unchanged. All trained models stay in the test, including any model with inconvenient mechanisms or poor performance. Head indices are model-specific.

The task presents four distinct key/value pairs and a uniformly chosen displayed query key. There are 16 key tokens and 16 output value classes. Full-vocabulary uniform guessing gives 6.25% accuracy; uniform choice among displayed values gives 25%. Reused training-validation data are exploratory and never counted as confirmation. Report the existing and new seed strata separately, individual seeds and descriptive ranges. Do not present example-only intervals as uncertainty over training populations.

## Inputs, calibration and blinding

Use **512** independently constructed calibration cases for per-position, per-head/component means, **1,024** discovery bundles, and **2,048** fixed confirmation bundles. Each bundle contains recipient and active/matched donors; all six models receive the same bundles within a split. The exact input arrays, generation code, RNG parameters and audit metadata are frozen before confirmation. Generator seeds alone are insufficient. The input preparer rejects whole bundles based solely on exact sequence identities and declared duplicate policy, never on model outputs. Calibration, discovery and confirmation bundles are mutually disjoint; no selected confirmation inputs may overlap the frozen forbidden set.

The forbidden set and its coverage include the relevant old/new training streams, reused validation, E1 discovery and frozen confirmation recipients/donors, and disclosed trained-model smoke inputs. The frozen input-generation/audit implementation and metadata specify exact coverage, candidate order, duplicate handling and rejection counters. Disclose any coverage limitation. Input preparation/audit is allowed before remote registration; model outputs on confirmation are prohibited. Any post-lock audit or hash failure aborts execution, preserving records and without silent replacement inputs.

An active resampling donor shares the recipient's query key and queried pair position but has a different correct value. A matched donor shares query key, queried pair position and correct value while changing other context. Each donor still has four distinct keys and values. Freeze all donor assignments. Matched donors are contextual perturbations, not automatically zero-effect controls.

Calibration tensors are fixed means of clean calibration activations, separately at each position for each seed. Do not recompute them using discovery or confirmation. The predictor may inspect authorized discovery summaries/raw arrays, training metadata, implementation and review documents, but no confirmation input arrays, confirmation model forwards, previews, outputs or forecast errors. It uses a deterministic numerical program without Torch/model imports. Role blinding is procedural on a shared filesystem, without OS-enforced isolation. Its allowed raw discovery access gives no access to reserved intervention outcomes.

## Interventions and exact novelty

L1 scientific layer is code layer 0; its `z` interventions affect **all four value positions [1,3,5,7]**. L2 scientific layer is code layer 1; its `z` interventions affect the **final query position [8]**. Interventions act before heads are concatenated and projected. Unselected heads, output-projection bias, residual paths and MLP remain. Whole-head-output corruption is not whole-layer deletion.

Discovery measures exactly **53** conditions: clean, all singleton head corruptions, all-four-head corruption for mean/zero/resample, matched resampling and the fixed wrong-position/no-op/MLP controls. There are **no pair, rescue or cross-layer interventions in discovery**. Confirmation measures those 53 plus all 92 reserved conditions:

| Primary novel family | Complete grid | Count |
|---|---|---:|
| pair | six pairs × two layers × mean/zero/resample | 36 |
| triple_rescue | four retained clean heads × two layers × mean/zero/resample | 24 |
| cross_layer | all 16 L1/L2 singleton pairs × mean/resample | 32 |

A sole-head rescue uses the same corrupted tensor as the all-head-corrupted condition and restores one head from the clean recipient. It is exactly equivalent to corrupting the other three heads and is counted once. No rescue result may be relabeled to evade the discovery boundary. For resampling, all selected heads in a condition use the same frozen donor and selected clean rescue heads use the original recipient cache.

Cross-layer operations run in causal order. After L1 corruption, obtain the current L2 cache, replace only the specified L2 head and rerun with the same upstream patch. Every unselected L2 head retains its response to the L1 intervention. Copying the entire unselected downstream cache from clean would test a different intervention and is prohibited. Frozen implementation checks compare this behavior with a direct live-hook oracle.

Synthetic preflight no-op and clean-restoration checks compare logits, with absolute tolerance **1e-6** on deterministic same-execution comparisons. The separate trained-model runtime validity gate uses maximum absolute **target-probability** discrepancy for no-op versus clean, tolerance **1e-6**, as recorded by the evaluator/scorer. Report appropriate numerical tolerances for batch-versus-row or independently implemented oracle comparisons separately. Check clean equivalence to E1, selected-head/position isolation, donor cache immutability, head-order/union invariance, all-head clean rescue and live cross-layer recomputation. A failed implementation control prevents an unqualified mechanistic claim; it does not authorize dropping an affected result. Numerical locality controls do not support a scientific mechanism by themselves.

## Frozen explanation and quantitative forecasts

`predictor.py` consumes only discovery probabilities and fixed condition specifications. Its second-order log-odds rule uses singleton changes and the all-head residual to distribute within-layer interactions by singleton head strengths; it assumes zero explicit cross-layer interaction. The complete formula, clipping/floor constants, limitations and scientific alternatives are in `PREDICTION.md`. No unseen response is used to choose a coefficient or hyperparameter. `predictions.json` provides **870 numeric mean target-probability forecasts**, 145 for each of six seeds, with fitted quantities and source hashes. Familiar/control forecasts are discovery means and are secondary.

The practical bound for each forecast is absolute mean-probability error **<=0.10**, clipped to probability support at endpoints. This is a prespecified useful-error tolerance, not a calibrated 90%/95% predictive interval. No claim of coverage for individual examples or independence of all 552 novel model-condition cells is made.

Freeze `conditions.json`, both predictor and baseline numerical forecasts, all predictor/scoring/input/runner/model code, checkpoints and hashes, fitted calibration tensors, exact selected inputs and audit metadata, protocol/review files and relevant runtime metadata in a public GitHub preregistration. Read back the exact remote commit/tree and establish that the frozen file bytes match it, then verify again before any confirmation forward pass. Preserve timestamped remote-readback evidence. A commit's existence alone is insufficient. All E2 result artifacts belong in `outputs/experiment2/confirmatory`; preserve discovery and E1 artifacts independently. No forecast, model, seed set, condition, gate or threshold may be quietly revised after freeze.

## Scoring, baselines and uncertainty

The primary endpoint is **mean original-target probability** per fixed model and condition. Original-target accuracy and target-logit minus best-other-logit margin are secondary. Define primary MSE as the average of the three within-family mean squared forecast errors, weighting pair, triple_rescue and cross_layer **equally (1/3 each)**. RMSE is its square root. Clean/familiar/control conditions are excluded from the primary loss and reported separately. Report family losses, every predicted/observed mean, signed/absolute errors and failure identities; never select a favorable subset as primary.

Freeze and score the seven baselines in `baselines.py`. The original five are zero-effect (predict clean), additive singleton probability changes with clipping to [0,1], multiplicative singleton probability-retention ratios relative to clean with denominator floor 1e-6, count-linear interpolation, and count-logit interpolation. The count rules interpolate the selected singleton values with the all-head endpoint using weight `(number_corrupted-1)/3`; logit probabilities are clipped to [1e-6,1-1e-6]. For cross-layer count rules, multiply the per-layer retention ratios relative to clean. On familiar/control conditions all baselines except zero-effect use the discovery empirical mean. Two additional baselines were selected after discovery and before confirmation to match the predictor's access to paired raw probabilities: case-logit-additive sums per-case singleton log-odds changes relative to clean, then averages sigmoid outputs; case-logit-count interpolates each case's selected singleton average and all-head endpoint on the log-odds scale with the same count weight, combining cross-layer shifts additively relative to clean before sigmoid/averaging. Both clip probabilities for log odds at 1e-6. These frozen formulas, not a verbal label, are authoritative.

The AI predictor and the two added case-logit baselines preserve per-case paired discovery probabilities; the original five use condition means. This amendment strengthens the information-matched comparison before outcomes are available. A gain would support the complete frozen rule, without uniquely attributing it to mechanistic insight. Report all baselines and the strongest outcome comparator, even when it defeats the predictor.

Use **2,000** bootstrap replicates, NumPy RNG seed **6200001**, generating multinomial weights for entire confirmation case bundles. Keep all interventions and donor/recipient measurements paired and use **the same weight matrix across all six models**. Calculate percentile 95% intervals for balanced MSE and AI-minus-best-baseline MSE. In each replicate the best baseline is the minimum loss among all seven, recomputed in that replicate; this stringent comparison avoids claiming superiority only to a selected weak baseline. These intervals condition on models, fixed calibration, discovery and fitted forecasts; they do not propagate fitting or training uncertainty. Accuracy intervals use Wilson's method; normal-approximation mean-probability intervals are descriptive, not simultaneous multiplicity-adjusted bounds.

Practical predictive success requires **balanced RMSE <=0.10 AND at least 80% of 92 novel conditions within 0.10 (>=74 conditions)** for each seed. Global practical success requires every seed to pass both adequacy gates and the distinct validity checks: clean accuracy >=95% and runtime no-op maximum absolute target-probability error <=1e-6. Report descriptive forecast scores even when validity fails, labeling their interpretation accordingly. Added forecast value requires the **upper endpoint of the paired 95% AI-minus-best-baseline MSE interval to be strictly below zero in each of all six seeds**. Report these as separate gates; either, both or neither may pass. Any combined claim requires both categories. Existing seeds 0–2 and new seeds 3–5 remain separate reported strata. Descriptive across-seed ranges are not confidence intervals.

## Failure and claim boundary

There are no exclusions by accuracy, seed, head, position, corruption, intervention or forecast error. Keep all 2,048 accepted cases even when recipient or donor behavior is wrong. Nonfinite/missing outputs, failed integrity checks or execution failure indicate an incomplete/failed test; preserve partial artifacts and errors. Repairs require a disclosed separate protocol rather than an unreported retry that changes the scientific test. An inaccurate predictor is a valid scientific result and must not be rewritten after seeing the novel grid.

A successful experiment would demonstrate prospective predictive utility for this exact corruption/rescue grid in six small trained transformers, including three new training seeds. It would not establish unique circuit semantics, general natural necessity, human-independent discovery of supplied hypotheses, or general AI self-understanding. The E1 conclusions and E2 discovery were available before prediction; the explanation is discovery-guided and its underdetermined interaction assumptions are the object of this test.
